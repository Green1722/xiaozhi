# S200 实测与主动播报交接

更新于 2026-11-16。

## 已完成并验证

1. 电脑通过蓝牙接收 S200 的认证广播。现场人员确认解析的体重和秤面一致。身高用身高尺测量，由操作人员录入。
2. 电脑以独立测量设备身份通过 TLS 和 MQTT 向华为云 IoTDA 上报。IoTDA 返回 PUBACK，转发规则将上报送至开发者空间体检服务。使用业务 API 查到了同一编号的 `measured` 记录，并核对了身高、体重、测量时间和 BMI。
3. 现场对小智说「查询体检数据」。日志记录了 MCP 工具调用以及云端记录匹配，现场人员确认小智播报一致。此次验收使用电脑作为采集网关，小智板负责查询和语音。
4. 验收后停用了测试转发规则、DevBridge 临时托管和本机 MCP 桥接。转发规则保留对 S200 采集设备的过滤条件。

## 主动播报增量

本机程序已接通以下顺序。输入本次测得的身高，等待 S200 的新读数，上报 IoTDA，按记录编号和实测字段确认业务入库，随后请求小智主动播报。话术依次包含身高、体重、BMI、成人参考范围解读和一条生活建议。已确认适用成人参考范围时可启用成人分级，年龄未知时提供通用复测建议。BMI 解读依据[国家卫生健康委《体重管理指导原则（2024 年版）》附表 1](https://www.nhc.gov.cn/ylyjs/zcwj/202412/75cb79c171c94def9e768193e65484f7.shtml)。

本地测试覆盖新读数组装、采集失败、播报内容顺序、年龄未知处理、同一记录重复请求和推送超时。HTTP 接受与设备出声分别验收。当前缺少指向现有小智设备的 HTTPS 主动推送接口，整条主动播报链路待实机验收。已验证的 MCP 路径由语音查询触发。

## 彩排和复验步骤

1. 在开发者空间恢复体检服务和 DevBridge 托管。检查 `GET /healthz` 为 HTTP 200，未授权访问 `GET /api/exams` 为 HTTP 401。
2. 在 IoTDA 恢复 S200 上报转发。核对设备过滤、HTTPS 转发目标和云端 `measured` 映射。测试前准备电脑蓝牙、秤和身高尺。
3. 在原联调电脑，从项目仓库目录启动本机采集脚本。下面的 175 仅作命令示例，须替换成本次测量的身高。

   ```powershell
   & .\.venv\Scripts\python.exe '..\私有配置\s200\send-measured-iotda.py' --publish --height-cm 175
   ```

4. 若复验已跑通的问答播报，启动本机 `start-xiaozhi-iotda-measured.py`，说「查询体检数据」，听取并核对本次结果。若验收主动播报，先配置现有小智设备的 `XIAOZHI_TTS_PUSH_URL`，第 3 步加 `--announce`，确认适用成人参考时再加 `--confirmed-adult`。现场测量后不发出语音指令，核对板端主动播报的内容，并记录是否有实际播放。推送超时先核对设备是否已开口，再决定如何补测。
5. 拍摄时依次展示身高录入、秤面读数、IoTDA 上报、业务记录和小智播报。测试后关闭临时转发、托管和桥接。命令引用的采集脚本、设备配置和实测记录存放在原联调电脑的私有目录。
