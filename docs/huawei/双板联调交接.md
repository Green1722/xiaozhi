# 双板联调交接

此前已用模拟设备实测 IoTDA 自动转发、SQLite 入库及外部鉴权查询。原联调规则和临时托管在验证后已停用。证据及恢复顺序见 [云端联调实测](云端联调实测_2026-11-05.md)。

## 旧桥接的离线补传

当前仓库独立实现了 SQLite 补传。旧码道包仍留在云端，留待后续归档与差异审阅。补传适用于由 Python 桥接发起的 HTTP 上传。ESP32 直连 IoTDA 的设备侧断网缓存需在实机链路中单独验证。

在运行桥接的同一用户下，为单个进程指定持久化数据库路径。启用现有上传配置后，额外设置以下变量：

- `PHYSICAL_EXAM_UPLOAD_QUEUE_PATH` 为该进程专用的绝对数据库路径。
- `PHYSICAL_EXAM_UPLOAD_URL` 指向已验证的体检服务 `/api/exams`。
- `PHYSICAL_EXAM_INSTRUMENT_ID` 填已确认的仪器标识。
- `PHYSICAL_EXAM_UPLOAD_API_KEY` 从现场私有配置注入。

启用后先落盘再上传。临时网络错误由后台每五秒重试，服务恢复后继续发送。按目标地址、仪器与记录 ID 区分待发记录，HTTP 409 等数据错误留在队列并标记状态。队列最多保留 1000 条，满时拒绝新增并记录错误。联调时用同一数据库路径重启桥接，保持目标 URL 一致。数据库含测量值，应存放在当前操作用户的私有目录。通过 `outbox.rejected` 检查需人工核对的条目。

## 明天接板顺序

1. 记录两块板的型号、现场固件、接线及原 MQTT 配置。先用现有链路测一次并听播报，保留稳定基线。
2. 云端按联调记录恢复服务、启动临时托管。先用原模拟设备验证查询与入库，再准备实机设备身份和对应过滤条件。
3. 测量板接入 IoTDA 使用独立设备身份。服务端将它映射到对应仪器并标记 measured。按 `PhysicalExam` 服务上报 `record_id`、`height_cm`、`weight_kg`、`measured_at`。单位分别为厘米、千克，时间为 UTC ISO 8601，重传沿用原 ID、原时间与数值。
4. 以同一条 ID 对照测量板输出、IoTDA 属性、云端数值及小智实际播报。分别记录上传接收和设备播报结果。带声音的录像或设备回执用于核对播报完成。
5. 验证实机断网恢复和第二次连续测量。断网时分别检查测量板接入 IoTDA 的路径与旧桥接到业务服务的路径。每次选择一条业务入库路径，避免同一次测量被两条路径分别记录。
6. 结束先停 IoTDA 规则，再停临时托管。将模拟记录与实机证据分别标注。

参赛材料可引用既有华为云 IoTDA、开发者空间、码道和 DevBridge 的实测证据。存储按 SQLite 描述，最终演示以现场实测为准。

### 实测设备接入顺序

1. 核对板卡型号、SDK 和当前固件目标，记录仪器接口和单位。用独立的 IoTDA 设备身份接入，将凭据保存在私有配置。
2. 在体检服务的设备映射中为该身份绑定仪器编号和 `measured`，并配置匹配该设备的 IoTDA 转发条件。保留模拟设备的 `synthetic` 映射。
3. 先发一条实际测量，从板端日志取得原编号，再核对 IoTDA 与业务库。确认仪器编号、来源、时间、身高、体重及 BMI 后，用同一编号检查小智查询。
4. 用同一报文复验去重，再做测量板断网恢复。记录有无补传、实际入库条数和小智播报结果，按现场验收表留证。
