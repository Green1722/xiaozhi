# 智能体检播报现场验收与演示脚本

目标链路为测量板 ESP32 → 华为云 IoTDA → HTTPS 转发 → 云端体检服务 → MCP → 小智播报。模拟链路的验证范围见 [IoTDA 双样本验收](IoTDA双样本实机验收.md)。

## 现场稳定版冻结

先记录两块板各自的型号、固件文件、源码提交、构建环境和当前工作接线；保存正在使用的 MCP 启动配置及依赖清单。凭据只在现场配置中保存，不入公开仓库。先用当前固件完成一次测量和播报，再开始替换云端配置。无法确认稳定版本时，不烧写、不覆盖原工作目录。

## 演示前必验

| 项目 | 操作与通过条件 | 留证 |
|---|---|---|
| 云端存活 | 访问 `/healthz`，响应正常；确认运行提交及数据目录 | 时间、响应、提交 |
| 鉴权 | 未带密钥访问记录接口被拒绝，带密钥可查询 | 脱敏请求结果 |
| 标准模拟样本 | `source=synthetic`，175cm、70kg，BMI 为22.86；页面明确标模拟 | 请求、页面 |
| 幂等与冲突 | 同仪器同ID相同内容重传不增行；改动内容返回409且原值不变 | 前后行数、状态码 |
| 多仪器隔离 | 两个不同仪器使用同一个源ID，两条数据均保留，按仪器筛选正确 | 查询结果 |
| 服务重启 | 记录入库后重启服务，原记录仍可查询 | 重启前后查询 |
| 断网补传 | 断开桥接到云端网络，测量入本地持久队列，重启桥接，再恢复网络，最终仅入库一次 | 队列、日志、云端记录 |
| 真实测量 | 使用实际仪器测量；对照仪器屏幕、MQTT原始值与云端值，确认单位与缩放 | 同一记录ID与时间 |
| 小智查询 | 语音请求最近一条，返回对应仪器与本次测量，不能读出前一人的记录 | 连续录屏/录像 |
| 实际播报 | 现场听到正确语音；MQTT发送成功仅标发送被接受，无设备回执时保持未确认 | 含声音的连续录像 |

断网与重启仅对本项目进程/链路实施，不停止共享 MQTT Broker 或无关服务。软件样本不能证明仪器测量精度；精度需仪器型号、校准或参照测量证据。

## 建议连续演示顺序

1. 简述双板分工和云端用途，展示真实码道任务、代码差异和测试结果。
2. 演示模拟数据的鉴权、BMI计算与页面查询，明确说明是模拟样本。
3. 实际仪器完成一次测量，保持同一条记录ID贯穿测量板上报、IoTDA、云端页面、小智查询与播报。
4. 展示重复上报不重复入库、设备侧断网恢复与服务重启后留存（以实际通过的项目为准）。
5. 说明已用的具体华为服务、当前免费开发环境的访问/休眠限制，以及尚未接入的RDS、MaaS或设备回执；不将SQLite称作RDS。

只录无真实身份的团队自测或模拟数据；录像包含操作全程与声音，不通过剪辑拼接不存在的闭环。外部访问链接和API密钥分开交付，公开视频遮挡密钥和登录票据。

## 仍需团队提供的参赛证据

学校、队名、成员和指导老师的准确资料；目标用户访谈和实际需求证据；原创增量与上游许可证说明；仪器型号与单位协议；硬件计量依据；双板实机连续演示；真实码道过程与云服务使用证据。信息收集表中的缺项按真实材料填写，不用推测代填。

吴振毅负责仪器与测量板，高睿恩负责云端与记录核对，朱倩颖负责小智播报和拍摄。先填写仪器型号、测量板型号与固件版本，再记录下表。精度验收需填写参照仪器和依据，误差按“实测值减参照值”分别记录身高和体重。

测量板使用独立 IoTDA 设备身份。按 `PhysicalExam` 上报 `record_id`、`height_cm`、`weight_kg`、`measured_at`。身高用厘米，体重用千克，时间用以 `Z` 结尾的 UTC ISO 8601。设备身份由服务端映射至仪器与 `measured` 来源，BMI 由服务端计算。重传保留同一编号、时间和数值。实际板卡的仪器接口、量程和校准依据待确认。

拍摄时先拍仪器与两块板的全景，再连续记录一次实际测量、仪器读数、云端同编号记录和小智播报声音。重复上报与断网恢复可各录一段，画面仅保留验收所需的脱敏信息。
